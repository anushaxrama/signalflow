01 / THE PROBLEM

Reliable decisions start before the dashboard.

Public grid data arrives with missing actuals, revisions and reporting delays. A useful carbon-aware compute tool needs to preserve those distinctions. SignalFlow validates real NESO records, retains raw provenance and makes source freshness visible.

02 / THE SYSTEM

One contract. Two ingestion paths.

NESO API→Python / optional Kafka→Validate + store→FastAPI + analytics

The verified local path uses Python, SQLite and FastAPI. The repository also implements PostgreSQL storage, Kafka producer/consumer and dead-letter transport, dbt staging and daily marts, and an Airflow reconciliation DAG. The complete container path has passed local integration checks with real public data.

04 / ENGINEERING TRADEOFFS

Correctness is a product feature.

Replay without duplicate projections. A unique raw-event claim and its analytical writes share one transaction. Kafka offsets commit only after durable processing; cross-system exactly-once delivery is not claimed.

Unknown stays unknown. Missing actuals remain null. The calculator requires observed, contiguous intervals. Statistical alerts use a documented rolling baseline.

Operational evidence over status theater. Freshness uses the source interval end. Failed ingestion runs and validation errors remain inspectable. A green dataset status does not prove every infrastructure service is running.

05 / VALIDATION & NEXT STEPS

Clear about what has been proven.

The local pipeline, API, analytics and dashboard were exercised with real data. Automated tests cover replay, revisions, failures, missing values, scenario math, API boundaries and simulated Kafka commit behavior. Browser checks exercise the time filter and workload form.

All 37 tests passed against both SQLite and PostgreSQL. Real Kafka delivery and exact replay passed with zero consumer lag. dbt built two models and passed 12 quality tests; the Airflow DAG completed all three tasks. Remote GitHub Actions, throughput benchmarks and cloud deployment remain future verification steps.
